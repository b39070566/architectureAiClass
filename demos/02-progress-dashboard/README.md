# Stage 03 + 04 · 建案進度儀表板

純 HTML／JavaScript 的儀表板，支援上傳 CSV 即時重繪。
**同一份檔案帶兩個階段**：Stage 03 是資料寫死的靜態版，Stage 04 加上上傳功能。

## 兩個階段怎麼切

| 階段 | 打開的網址 | 畫面 |
|---|---|---|
| Stage 03 | `index.html?stage=3` | 「換一份資料」整段被收起來，就是一份靜態儀表板 |
| Stage 04 | `index.html` | 出現「選擇 CSV 檔案」，可以上傳並即時重算 |

帶課順序：先開 `?stage=3`，講完「這些數字寫死在檔案裡，要更新就得請 AI 重做一次
整份網頁」這個痛點，再把參數拿掉重新整理——上傳功能就出現了。痛點和解法在同一個
畫面上先後出現，比開兩個分頁對照更有感。

## 檔案

```
02-progress-dashboard/
├── index.html
├── built-in-data.csv     網頁內建示範資料的表格版
└── upload-sample.csv     另一份測試資料，用來驗證上傳
```

- **`built-in-data.csv`** 是 Stage 03 的教具：頁面上那 7 個案場的數字，就是這張表。
  把 CSV 和網頁並排看，講「表格 → KPI／進度條／狀態」這個對應關係是怎麼發生的。
- **`upload-sample.csv`** 是 Stage 04 的教具：20 個案場、名字跟內建資料完全不同，
  上傳後畫面整個換掉，證明「換一份資料，畫面真的會跟著算」。

兩份都帶 UTF-8 BOM，Windows Excel 可以直接雙擊打開不亂碼。
上課時也可以直接讓學員自己準備一份同格式的 CSV 上傳。

## 重點觀念（課堂講解用）

- **做得到**：選檔案上傳 CSV，瀏覽器端 JavaScript 讀取並即時重算，完全不需要伺服器。
- **做不到**：資料不會被儲存，重新整理頁面就回到示範資料；也不會跨裝置、跨使用者同步——
  因為沒有連接任何資料庫或後端服務。
- 適合「週報／月報」這種定期產出快照的場景，不適合需要多人即時協作更新的場景。
  這不是缺點，週報本來就是快照。

## 編碼注意事項（Windows 使用者必看）

Excel 在 Windows 上另存 CSV 時，預設選項是「CSV (逗號分隔)」，存出來的檔案是
**Big5** 編碼，瀏覽器讀取會整篇變亂碼。

存檔時請選 **「CSV UTF-8 (逗號分隔)」**，才能正常顯示中文。

這件事務必在學員動手前講，不然會有一半的人卡在亂碼，時間全部耗在這裡。

網頁本身也有做保護：上傳時會自動偵測編碼（UTF-8 讀不出中文就改用 Big5 試一次），
並且在欄位對不上、資料是空的、或數字欄位格式不對時，畫面上會顯示錯誤提示說明
問題出在哪裡，而不是直接空白。

## CSV 欄位格式

| 欄位 | 說明 |
|---|---|
| 案名 | 建案名稱 |
| 階段 | 目前施工階段 |
| 完成率 | 0–100 的整數 |
| 已售戶數 | 整數 |
| 總戶數 | 整數 |
| 狀態 | 正常 / 落後 / 即將完工 |

資料為虛構示範內容，非真實銷售或施工資訊。
