# vibe coding 課程教材 · 漸進式四階段架構

建商員工班（非資訊背景，3小時課程）教材範例。四個階段共用同一個虛構建案
「翠湖苑」當貫穿主題，每階段只疊加一個新概念，學員不用每階段重新理解情境。

## 資料夾結構

| 資料夾 | 對應階段 | 說明 |
|---|---|---|
| `00-curriculum-overview/` | 總覽 | 四階段架構一頁式總覽，可直接給老師/學員看課程地圖 |
| `01-info-website/` | Stage 01 | 建案介紹單頁網站（純靜態，第一次生成） |
| `02-info-website-image-swap/` | Stage 02 | 同一份網站＋課堂說明，教圖片檔怎麼跟網頁連結 |
| `03-static-dashboard/` | Stage 03 | 進度儀表板，數字寫死在網頁裡（無上傳功能） |
| `04-interactive-dashboard/` | Stage 04 | 進度儀表板，支援上傳CSV即時重繪 |

## 怎麼用

每個資料夾都是一份可以直接用瀏覽器打開的獨立網頁（`index.html`），彼此不互相依賴。
`03-static-dashboard` 和 `04-interactive-dashboard` 刻意用同一份資料、同樣的視覺風格，
只差在「有沒有上傳功能」——上課時把兩個並排展示，最能讓學員感受到 Stage 04 多學的
那個能力（事件與狀態）到底解決了什麼問題。

## 課程邏輯

1. **Stage 01 → 02**：從「別人的範例」到「我的東西」。學員弄懂 `src="images/hero.jpg"`
   在講什麼，就能把照片放進資料夾自己換圖，第一次產生擁有感。
2. **Stage 02 → 03**：從「內容網站」跳到「資料工具」。視覺語言刻意切換
   （建築文宣風格 → 建築製圖藍圖風格），提醒學員這是不同性質的任務。
3. **Stage 03 → 04**：從「靜態快照」到「可互動」。這一步順勢帶出資料庫/API的
   邊界在哪裡，當作未來延伸的鉤子，不用在3小時內真的教。

Stage 02 和 Stage 04 都在處理「網頁怎麼取得外部檔案」，但方向相反，剛好互補：
Stage 02 是**檔案放在資料夾裡、網頁去讀它**（改檔案就好，不用改網頁）；
Stage 04 是**使用者當場上傳檔案、網頁即時運算**（不會存下來，重新整理就沒了）。
兩邊都體會過，Stage 04 最後講「為什麼想要即時同步就得接資料庫」時會好懂很多。

詳細架構說明、難度曲線、階段對照表，見 `00-curriculum-overview/index.html`。
